# Argus MVP: build plan (PM execution spec)

**Goal vector (every agent points here):** deliver everything in [`argus-mvp-spec.md`](argus-mvp-spec.md) that can be built without the physical hat. That covers the modular Pi software, the backend, the LLM report pipeline and the dashboard. All of it must be proven by a one-command mock end-to-end demo. When the hat arrives, a teammate should be able to plug it in, run `install.sh`, pair it, and see a real report. The only code they should need is their own sensor scripts, pasted in as `team` implementations.

The product spec is the source of truth for *what*. This file covers *how, who and in what order*. If the two conflict, the product spec wins. The PM then fixes this file.

## 2. Tech stack

| Layer | Choice | Notes |
|---|---|---|
| Pi runtime | Python 3.11, `uv` project, `pydantic` v2, `numpy`, `pyyaml`, `httpx`, `typer` (CLI), `pytest` | Hardware libs (`picamera2`, `lgpio`, `smbus2`, `adafruit-circuitpython-*`) are an **optional extra `[pi]`**, imported lazily inside `argus` impls only, so the laptop/CI never needs them. |
| Clip muxing | ffmpeg `-c copy` | Mock camera writes H.264 segments generated by ffmpeg. |
| Shared contracts | `contracts/*.schema.json` (JSON Schema) | Single source of truth for the event payload, sensor trace and report JSON. Python (pydantic) and TS (zod) models are each tested against these schemas. |
| Backend | Local Supabase (Postgres 15, Storage, Auth, Realtime) via Supabase CLI. Migrations in `supabase/migrations/`, seed in `supabase/seed.sql` | Hosted Supabase later = same migrations. |
| API | Next.js 15 App Router route handlers (`/api/devices/*`, `/api/events/*`) | Device token auth → signed Storage upload URLs. |
| Report worker | Node 22 TS process in `worker/`, polling or listening for `events.status='uploaded'` | Modes: `fixture` / `gemini` / `hybrid` (Gemini video → Claude Opus 5.5 report, structured outputs, adaptive thinking, `fallbacks: "default"`). Every call is logged to `analyses`. |
| Dashboard | Next.js 15, TypeScript, Tailwind v4, shadcn/ui, Recharts (synced sensor chart), Motion (animations), `@supabase/ssr` | pnpm workspace. |
| Shared TS | `packages/shared`: zod schemas + types generated from `contracts/` | Used by web + worker. |
| Tests | pytest (device), Vitest (shared/worker/web units), Playwright (one E2E smoke) | |

## 4. Alignment protocol (how agents stay pointed at one goal)

1. **Every agent prompt starts with the same header:** the goal vector above, links to both spec files, the `contracts/` folder, and the rule *"Do not modify `contracts/` or another task's files. If a contract is wrong or missing, stop and report it."*
2. **Contracts first:** cross-boundary shapes (Python ↔ backend ↔ worker ↔ web) are fixed in M0.2 before parallel work starts. Both sides test against the same JSON Schema files.
3. **File ownership:** each task lists the paths it owns. The PM rejects diffs outside them.
4. **Agent output format:** files changed · tests run with results · deviations from the spec (with reason) · open issues. The PM reads the diff and does not rely on the summary alone.
5. **Merge gate (PM):** diff review against spec sections → run that milestone's tests in the main worktree → commit `feat(<area>): <task id> <summary>` → update the task board in §6.
6. **Loop:** spawn every unblocked task → on each completion, review, merge or send back (max 2 rework rounds, then escalate to the next model tier) → re-check blocked tasks → repeat until the M6 gate passes.

## 5. Blockers needing the user
- **Homebrew + Docker Desktop installs need your macOS password once.** Run the Homebrew installer with `!` in this prompt. Then, after `brew install --cask docker`, open Docker.app once.
- Keys later: `SUPABASE_URL/ANON/SERVICE` (only for hosted), `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`. Local mode needs none.
